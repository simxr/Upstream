# Product positioning

## Problem

Cloud and platform engineers often know the underlying technology but do not know which open-source issue is a responsible, useful place to begin. Language-only discovery mixes Kubernetes controller work with unrelated Go projects, while contributor analytics products answer questions about communities rather than the next task an individual should take.

## Positioning

> Upstream is Good First Issue for people who already think in Kubernetes and Terraform—organized by domain and contribution shape instead of only programming language, curated from the CNCF and AWS ecosystems, and matched against what the user actually knows.

Good First Issue is direct inspiration for the curated issue-card browsing pattern. Upstream's differentiation is its cloud-native scope, domain and contribution-shape taxonomies, personal skill matching, plain-language audit trail, and lightweight personal journey tracking.

## Primary user

An experienced infrastructure engineer who is new to upstream contribution, not new to the technologies involved.

## Product principles

- Curated beats comprehensive.
- Explain a recommendation; never hide it behind a score.
- Optimize for choosing and starting a real task.
- Automate research and bookkeeping, not community participation.
- Keep v1 static, inexpensive, and understandable.

## Non-goals

- Automated code, comment, issue-claim, or pull-request generation.
- User accounts, authentication, or multi-tenancy.
- ML or embeddings-based matching.
- Crawling public GitHub outside the configured allowlist.
- Estimated effort or difficulty claims.
